### Task 1: runtime 加固波

**Files:**
- Modify: `packages/runtime/src/ai-slot.ts`、`packages/runtime/src/fetch-tree.ts`、`packages/runtime/src/live.ts`
- Modify: `packages/runtime/src/ai-slot.test.ts`、`packages/runtime/src/fetch-tree.test.ts`、`packages/runtime/src/live.test.ts`

**Interfaces:**
- Consumes: 现有实现。
- Produces: 行为收紧——restore 使在途响应失效；SSE 骨架永不可覆盖终树；onSkeleton 回调异常不吞响应；SSE 解析容忍 CRLF；readBody 完整解码；live-src 自带 query 时 URL 正确拼接。

逐项（每项先写失败测试，再修）：

- [ ] **1a. `restore()` 使在途 load 失效**
  测试：load 在途（fetch 挂起）时调用 `restore()`，随后响应到达（合法 AI 内容）→ flush 后仍显示兜底内容（响应被丢弃）。
  修复：`restore()` 开头加 `this.loadSeq += 1;`。
- [ ] **1b. SSE 骨架永不可覆盖终树**
  测试（fetch-tree 或 ai-slot 层，选能稳定复现的）：构造骨架渲染慢于终树的场景——用一个首次调用返回挂起 Promise、第二次立即返回的 renderer，骨架先开始渲染（挂起）、终树渲染先完成 setContent、骨架随后 resolve → 断言最终 DOM 是终树内容。
  修复：`ai-slot.ts` 的 `load()` 内加闭包标志 `let finalApplied = false;`：终树 `setContent` 前置 `finalApplied = true`；骨架 `.then` 回调内增加 `if (finalApplied) return;`（在 seq 检查旁）。
- [ ] **1c. onSkeleton 回调同步抛错不吞响应**
  测试（fetch-tree.test.ts）：onSkeleton 抛错的 SSE 响应 → 终树仍正常返回。
  修复：`readSSE` 中 `opts.onSkeleton?.(data.tree)` 包 try/catch（catch 内注释「回调异常不影响主流程」）。
- [ ] **1d. SSE 解析容忍 CRLF + TextDecoder flush**
  测试（fetch-tree.test.ts）：帧以 `\r\n\r\n` 分隔、行尾 `\r\n` 的 SSE 体 → skeleton 回调与终树返回正常。
  修复：`readSSE`/`readBody` 的文本先 `.replace(/\r\n/g, "\n")` 再分帧；`readBody` 循环结束后追加 `decoder.decode()`（无参 flush）拼接。
- [ ] **1e. fetchComponentTree malformed-JSON / 缺 tree 字段返回 null**
  测试（fetch-tree.test.ts）：`res.json()` reject 的响应 → null；body 无 `tree` 字段的合法 JSON → null。现状应已通过（构造上安全），测试为锁定。
- [ ] **1f. live-src 自带 query 时 URL 拼接用 `&`**
  测试（live.test.ts）：`src: "/ai-invalidate?token=abc"` → 请求 URL 为 `/ai-invalidate?token=abc&slot=hero`。
  修复：`subscribeInvalidation` 拼接处改为 `` `${opts.src}${opts.src.includes("?") ? "&" : "?"}slot=${encodeURIComponent(opts.slot)}` ``。
- [ ] **1g. live-src 覆盖分支测试 + 跨 chunk 分帧测试**
  测试（live.test.ts / ai-slot.test.ts）：① ai-slot 设 `live-src="/custom/channel"` → 订阅请求发往 `/custom/channel?slot=hero`；② invalidate 帧跨两个 chunk 到达（`event: inval` + `idate\ndata: {...}\n\n`）→ 回调仍触发。现状 ②应已通过，测试为锁定。

- [ ] **Step 1: 实现**

`ai.mjs` 的 `createHandler` 默认 llm 参数改为按环境选择：

```js
import { createAiRenderHandler, createOpenAIClient, MemoryCacheStore, withRetry } from "@ai-slot/proxy";

/** 真实 LLM（设置了 OPENAI_API_KEY 时）；否则 null 表示用 mock。 */
function realLLM() {
  const apiKey = process.env.OPENAI_API_KEY;
  if (!apiKey) return null;
  return withRetry(createOpenAIClient({
    apiKey,
    baseUrl: process.env.AI_BASE_URL, // 可选：OpenAI 兼容端点
  }));
}

export async function createHandler({ llm, cacheFile } = {}) {
  const resolved = llm ?? realLLM() ?? mockLLM;
  const models = process.env.OPENAI_API_KEY
    ? {
        developer: process.env.AI_MODEL_DEVELOPER ?? "gpt-4o",
        user: process.env.AI_MODEL_USER ?? "gpt-4o-mini",
      }
    : undefined;
  // ……store 水合逻辑不变……
  return createAiRenderHandler({
    registry,
    llm: resolved,
    store,
    models,
    resolveSlot: (slotId) => slots[slotId] ?? null,
  });
}
```

注意：`createHandler` 现有签名 `{ llm = mockLLM, cacheFile }` 需改为 `{ llm, cacheFile }`（默认在函数体内解析），server.mjs 的调用（`AI_LLM=down` 注入 downLLM）不受影响。
