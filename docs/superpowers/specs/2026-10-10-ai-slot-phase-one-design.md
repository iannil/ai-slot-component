# AI-SLOT 首阶段实施范围

日期：2026-10-10；状态：待执行的实施设计。上位设计：[产品演进设计](2026-10-10-ai-slot-product-evolution-design.md)。

本轮只细化两个可独立交付的子项目：官网 W0，以及数据交付 P0a。既有官网与组件路线图保留，P0b、版本管理、MCP 管理、平台插件并未被取消，也未计入本轮完成定义。

## 官网子项目

保留当前 React/Vite 双语单页与演示架构，调整首屏、行动入口、能力边界和公开资料。增加“与已有产品共存”的职责表：CMS 管事实，宿主管页面，AI-SLOT 管授权局部。三种 AI 职责分开显示；管理 MCP 标为规划中。现有公开 MCP 仍只读文档。

官网首轮不依赖 P0a 合入，不公布新函数已经发布；数据模式只说明可以接合规端点。暂不重做演示状态机或加入模拟审批后台，默认仍允许选择已有行业，改为任务说明和准确模拟标记。这是对上一轮 W2 范围的进一步分批。

## 数据交付子项目

新增 createRenderHandler，首期仅支持公开、确定性的 GET 数据交付；提供 ContentProvider 接口。resolveSlot 读取版本化数据快照，provider 只消费该快照并输出不可信组件树；服务端校验后交付。

保留 createAiRenderHandler 的实现和缓存行为。两入口共用 JSON/SSE 响应辅助函数、注册表与校验器，不在此阶段统一用户提示词缓存。原 AI 用户缓存前置行为已有测试；改变它是单独的迁移设计。未来 AI provider 统一不是本次任务。

缓存键包含 namespace、provider.id、registryVersion、slotId、contentVersion 和 promptVersion，不用现有 32 位 hash 隔离新路径。新入口仅供公开内容；不承诺鉴权/个性化数据隔离。源解析先于缓存读取，源失败返回 503，不跨源版本回退。默认 stale 为 0；只有调用方显式设置 staleMs 时可使用同一版本旧结果。缓存命中也重新校验结构，防止加载非法持久化值。

resolveSlot 与 produce 共用 8000ms 请求预算，提供 AbortSignal；超时返回 503，不写缓存。AbortSignal 无法强制中断不配合的外部代码，调用者须传给 fetch。新路径不重试 provider，不触发模型。无模型路径仍使用现有 ai_unavailable 错误码以保持消费端约定。

新增本地 JSON 数据源示例，真实 runtime 渲染；修改文件和版本后刷新槽位，无需重启服务或构建。该示例不代表商业 CMS 已兼容，也不是实时推送或权限管理功能。

## 共同约束（各计划原样引用）

- 项目文档与注释使用中文。
- AI 从不输出 HTML；组件树必须通过注册表校验后渲染。
- 保留原始兜底内容，不能把失败结果渲染为页面空白。
- Node >= 18；核心包不新增运行时依赖。
- 官网继续使用 aislot.dev；本次不迁移域名、不部署、不发布 npm。
- 仅修改任务列明文件；不暂存既有研究报告与其他无关未跟踪文件。
- 既有公开 MCP 只读文档，管理型 MCP 仍为规划能力。

## 验收

官网：双语、390px/桌面、CTA、可访问性基本操作、Agent 四通道、构建均可用，能力状态准确。

数据交付：无需 LLM 参数；非法树/超时/源失败受控返回；缓存版本与提供者隔离；prewarm 可序列化恢复；真实浏览器局部更新且原页面其他节点不变；旧 AI 单测与既有端到端测试不回归。
