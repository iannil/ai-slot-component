# 交付、缓存与收录边界

核对日期：2026-09-28。范围：当前仓库示例与运行时，不代表所有宿主应用。

| 阶段 | 实际产物 | 能证明什么 |
|---|---|---|
| 作者编写页面 | `<ai-slot>` 中的初始 HTML | 不执行 JavaScript 时仍有作者提供的内容 |
| `prewarm.mjs` | `ai-cache.json` | 预先生成组件树，命中缓存时减少模型调用 |
| 浏览器加载 | 获取组件树并调用渲染适配器 | 增强后的内容在浏览器中出现 |
| 已处理的获取或校验失败 | 使用兜底内容 | 该类失败不必导致槽位空白 |

预热不输出 HTML，也不等于 SSG 或 SSR。缓存失效、缺失或访客个性化请求仍可能调用模型。初始 HTML 与增强后的 DOM 不一定相同。

首次安装槽位、修改宿主模板或新增组件代码仍可能需要发布；只有已部署能力内的内容更新可独立交付。

## 如何复核

1. 按 README 启动默认 mock 示例，不需要 API key。
2. 查看网页源代码，确认初始响应包含作者提供的兜底正文。
3. 在浏览器中等待增强，比较槽位 DOM 与初始响应。
4. 运行 `node examples/plain-html/prewarm.mjs`，检查产物是 JSON 缓存。
5. 使用示例中的 `broken` 槽位观察校验失败后的兜底展示。

不要用缓存命中推断收录，也不要用成功渲染推断排名。Google 支持 JavaScript 渲染；索引仍受访问、内容与搜索系统判断影响。[官方说明](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)

## 应用边界

注册表与校验器约束组件名、属性和树形结构，不替代组件本身对 URL、样式与其他不可信属性的安全处理。宿主样式、组件异常、服务可用性及第三方资源仍需由应用负责。A2UI 兼容范围应以包文档和测试覆盖的消息版本、组件及事件为准，不等于完整协议认证。
