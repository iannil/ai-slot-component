# CMS 局部内容更新试点准备

## 当前状态

截至 2026-10-11，已完成自有 WordPress 参考站接入验证；尚无客户、客户站点授权、客户侧安装或真实配对任务。`slot-task-log.csv` 仅有表头，不能据此声称节省劳动、质量通过、付费意愿或试点成功。自有站与合成测试只验证技术路径。

客户安装的启动条件是先由站点负责人填写并确认[试点授权模板](pilot-consent-template.md)的全部字段，明确允许的只读源、操作、发布窗口、域名/CSP、数据范围及撤回责任人。未获得这些信息前，不启动客户侧安装，也不采集客户真实业务内容。默认仅记录各阶段用时和匿名错误码。

## 筛选与访谈记录

候选对象：维护已有站点、每月至少有重复介绍区更新任务的开发者或服务商。招募前确认维护权限与实际任务频率。访谈需记录：

- 现有平台能否原生完成同类局部更新；
- 每月此类任务数，以及最近一次任务的原流程步骤；
- 最难审阅的内容及原因；
- 愿意承担的接入时长；
- 对接入和持续使用的价格反馈。

目前没有真实访谈或反馈，以上均为待收集项。先选择一个非关键介绍区，在同一站点记录至少三项真实更新的 baseline/slot 配对任务；每次失败尝试另起一行，直至最终成功或停止。`quality_pass` 仅最终成功尝试填 `true`。创作、审阅、纠错、发布、支持均计入人工；机器等待单列。试点结束后用 `node docs/validation/analyze-pilot.mjs docs/validation/slot-task-log.csv <接入分钟> <维护分钟>` 分析。只有至少三项配对任务、baseline 与 slot 均最终质量通过、中位人工时间降幅至少 30%、扣除接入与维护后净节省大于 0，且无未授权发布、事实错误或严重页面错误，才可进入下一试点。未达到时不扩展。
