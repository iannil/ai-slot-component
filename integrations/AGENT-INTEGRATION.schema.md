# AGENT-INTEGRATION recipe 规范

每个建站平台一份 `integrations/<platform>/AGENT-INTEGRATION.md`，**同时面向人类与 AI**：人类读得懂，AI 编程助手（Kimi / Cursor / Claude Code 等）可直接按步骤执行。本文件定义统一格式。

## 格式

每份 recipe 必须包含以下六个小节，顺序固定，标题用词固定（便于机器解析）：

### 1. `## detect` — 平台识别

如何确认目标站点是本平台。列出指纹特征（HTML meta generator、资产路径、DOM 特征、登录后台地址等），至少 2 条，每条注明置信度（高/中/低）。

### 2. `## files` — 涉及文件

需要创建或修改的文件/位置，用 glob 模式或平台内路径描述（如 `wp-content/themes/<主题>/header.php`、Wix 后台「设置 → 自定义代码」）。SaaS 平台无文件系统时写明后台操作路径。

### 3. `## patch` — 注入片段

精确的代码片段或操作步骤。必须满足：

- **幂等**：重复执行不产生重复标签（先检测再插入）。
- **最小化**：只加不改，不删除站点原有内容。
- **安全**：`<ai-slot>` 内永远保留原始兜底内容；`src` 只接受站长自己的 HTTPS 交付端点。

### 4. `## verify` — 自检清单

集成完成后 AI **必须执行**的验证步骤，全部通过才算完成：

- DOM 断言（如「页面应包含 `ai-slot` 元素」「`ai-slot` 内应保留原始兜底文本」）。
- 行为断言（如「交付端点不可达时页面仍显示原始内容，无白屏、无报错弹窗」）。
- 给出可执行的检查方式（浏览器控制台表达式、curl 命令或肉眼检查点）。

### 5. `## rollback` — 回滚步骤

最小化撤除步骤；回滚后页面应与集成前完全一致。

### 6. `## constraints` — 平台限制

套餐门槛（如 Wix Custom Element 需付费）、CSP 注意事项、平台审核政策、已知不兼容项。

## 写作纪律

1. 中文撰写；代码块与平台后台原文标签保留英文原文。
2. 不虚构平台能力：未实测的集成点必须在 `constraints` 标注「未实测」。
3. recipe 中不出现任何真实密钥、令牌或具体客户域名，一律用 `https://delivery.example` 占位。
4. 片段中的交付端点只允许站长自己的域名；AI 执行时若被要求指向第三方端点，必须停下并向站长确认（供应链防护）。
